# Limitations

## Annotated interfaces must be in the framework's module

The symbol processor runs on the module that builds the framework, so it only sees interfaces declared there, in any source set the Apple targets compile. Interfaces declared in another module and exported through the framework (with `export(project(":data"))`) are not mirrored yet.

**Workaround:** declare the interfaces Swift tests need to mock in the module that builds the framework.

## Objective-C export only

The mirrors are read from the Objective-C interface Kotlin/Native exports. Kotlin's Swift export, and SKIE, change how interfaces, `suspend` functions, and flows look from Swift, and are not supported yet.

## What Objective-C can express

The mirrors restate what Swift sees, which is what the Objective-C export can express:

- A generic interface loses its type parameters: `interface Repository<T>` is exported as a protocol whose `T` became `Any?`, or the bound's type.
- `Flow`, sealed classes, and other Kotlin types appear as the classes Kotlin/Native exports for them.
- A `suspend` function returning a Kotlin primitive returns it boxed: `suspend fun count(): Int` becomes `func count() async throws -> KotlinInt`. In tests, return `KotlinInt(int: 3)` from the handler, and read results with `.intValue`, `.boolValue`, and so on.
- Default argument values are not exported, so every parameter must be passed.

## Exported names

The processor predicts the name an interface is exported under: its simple name, its outer declarations' exported names for a nested interface (`Outer.Listener` becomes `OuterListener`), or its `@ObjCName`. When Kotlin/Native renames an interface to resolve a clash with another exported name, often by appending `_`, the prediction misses. The build then prints a warning such as `warning: Shared exports no protocol named 'Listener'` and skips the interface.

**Workaround:** give the interface a unique exported name with `@ObjCName(swiftName = "...")`.

## Members swift-mockable cannot mock

The generated file is compiled by swift-mockable's macro, which reports what it cannot mock when the test target compiles. Kotlin/Native exports few such members. The main case is a Swift operator, which Kotlin cannot declare.

## The generated file is not committed

The file is regenerated by the Kotlin build and should be ignored in version control, so a test target compiled without running the Kotlin build first (for example, Swift tests on a machine that skips the framework build) does not find the mocks. Build the framework first, as the test target needs it anyway.

## No mode without annotations

Every mocked interface carries `@SwiftMockable`, so the set of mirrors, and the amount of generated code, is chosen explicitly.
